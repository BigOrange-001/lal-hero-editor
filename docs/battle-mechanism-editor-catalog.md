# 战斗机制与编辑器覆盖目录

生成来源：当前仓库实际配置与客户端复合机制参数契约。运行 `python -B scripts/generate_battle_editor_catalog.py` 更新。

当前 **1207 条技能全部可导入编辑器完整模板**；包含 **83 种原生动作、52 类复合机制、324 个复合机制可调参数**。这些是技能条目数，包含品质变体，不是去重后的英雄技能数。

## 从游戏逻辑到编辑器

| 游戏逻辑 | 编辑入口 | 导出字段 |
| --- | --- | --- |
| 施放等待、冷却、射程、生命条件、AOE、站桩 | 基础与触发 | `nativeTemplate.settings.pl` |
| 被动触发（0～19） | 基础与触发 → 被动触发方式 | `passiveTrigger`，绑定英雄时编译为 `skill_diff` |
| 伤害、控制、位移、召唤等执行步骤 | 动作 / 选敌 / 条件 / 附加效果 | `actions[].type/arguments` |
| 单动作选敌、上限、锁定、目标组、筛选 | 同页字段树 | `actionTargetPolicies/MaxTargets/Locks/Groups/PolicyArgs` |
| 成长、伤害分摊、说明、召唤与分身策略 | 成长 / 分组 / 召唤 / 联动 | `skillUp/skillUpPaths/damageShareGroups/manualSummonPolicy/manualClonePolicy` |
| 专属复合技能内部数值与条件阈值 | 复合机制内部数值与条件 | `abilityParameters` |

树中的列表索引从 0 开始；动作列表显示从 1 开始的可读序号。数字、开关、资源、列表与对象均有结构化控件，无需修改原始 JSON。原生复合机制保留游戏已有执行流程，数值与条件阈值由参数契约提供；增加新的脚本算法仍需开发游戏引擎。

## 身份、兼容与安全边界

模板的 `source/sourceDigest` 指向不可变原版机制来源，包内 `id` 是自制技能身份。编译器生成私有运行 ID，并另外写入受校验的机制来源标识；不能依靠改名绕过角色专属派发。来源变动需要重新导入审核，合包不会改变机制来源。

原生模板需要 `skill.native-template.v1`；1.0.3 机制与限时神佑条件需要 `skill.native-template.103`；通用事件被动需要 `skill.events.v1`。客户端在请求中声明支持。服务端检查激活、登录及玩法请求；仅升级编辑器不能让旧客户端执行新格式。原有命名字段的 16 动作格式继续兼容。

校验覆盖已知动作与形状、有限数值、参数范围、资源与单位引用、来源摘要、动作关联、成长路径和召唤策略。所有包仍经过相同的配额、依赖与冲突校验，不提供 AS3/SWF/eval 或外部代码加载。
