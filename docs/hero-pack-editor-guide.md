# 英雄工坊：Windows 英雄包编辑器

英雄工坊是离线的 Windows 图形编辑器，用于制作当前游戏的 `new` 英雄包和 `patch` 替换补丁，也可以把多个包合并为新包。它不连接游戏服务器、不读取玩家存档，不需要启动游戏。

## 打开程序

解压整个发行目录，双击 `HeroPackEditor.exe` 或“启动英雄工坊.cmd”。保留同目录的 `_internal` 和资源文件夹，不要只拷走一个 exe。

工程文件使用 `.lalhero`，可以保存未完成的草稿。游戏导入使用 `.heropack`，只有合法数据才能导出。两者用途不同，保存草稿不等于导出成功。

## 新建与包信息

新建时选 `new` 或 `replace`：

- `new` 创建拥有独立身份的新英雄，支持同包多个英雄、技能及相应补丁。
- `replace` 选择原有英雄，修改指定字段或技能槽，导出标准 `patch` 包。

在包信息中填写名称、作者和版本。带星号的是必填项。UUID 是包的永久身份，修改后会产生新的游戏身份；已有存档的角色不会自动迁移。普通内容更新应保留 UUID 并调整版本。

界面提供包、英雄和补丁的玩法渠道设置，以及补丁作用域设置。没有填写的开关继续沿用游戏默认规则；不支持或不适用的声明不会被当作实际功能。

## 英雄与数值

在工程树中新增英雄，填写或从现有英雄复制基础资料。基础属性和每级成长分别编辑，等级、品质、定位、行动类型、伤害类型、速度、射程、统御和技能关联均使用实际包字段。

数值框可以直接输入，也可以使用箭头和滚轮调整。合法范围显示在控件和校验提示中；超过等级上限后的最终属性同样受到游戏限制。

1.0.3 起，属性区域提供“按定位自动填充基准值”：先选择品质和战斗职责（输出／坦克／辅助），点击后会用同条件原版英雄的中位数覆盖四项基础属性、四项每级成长、速度、射程和领导力。定位说明与同职责原版分类完全匹配时进一步筛选，否则按战斗职责取值并提示。界面显示本次填充条件和样本数；成长直接统计原版成长字段，三个整数属性的中位数按四舍五入取整。没有样本时保持原值并提示。填充后可继续手动修改，不影响技能、图片和等级上限；改变定位不会自动覆盖已编辑数值，需要再次点击按钮。

“平衡性基准”显示真实配置中橙、紫、蓝、绿、白品质的角色面板，可按定位、品质和等级比较。品质对应 6／5／4／3／2。参考面板使用基础属性加每级成长，不包含装备、培养、羁绊、天赋等额外加成；不能将该表理解为实战胜率或强制平衡结论。

## 技能编排

1.1.0 起，全部 **1077 条原版技能**都可作为完整编辑模板，含品质变体。顶部“＋技能 → 从任意原版技能模板创建”可搜索技能名称或 ID；英雄技能槽的“创建并绑定 → 从原版模板创建并绑定”可直接创建本包技能并绑定当前槽位。技能页顶部还可选择模板替换当前内容，保留本地 ID。

导入后是本包独立技能，可以修改数据、保存、导出，并再次导入编辑。来源摘要与机制标识保留原生派发依据；不能把技能目录中的只读查阅或整项引用理解为模板编辑。带“先导入为模板”的技能应通过上述入口使用。

原生模板有四个编辑页：

1. **基础与触发**：名称、说明、被动触发方式、准备时间、冷却、射程、生命条件、AOE 与站桩许可。
2. **动作 / 选敌 / 条件 / 附加效果**：可拖动动作，新增已有原生动作预设、复制或删除；右侧展开并选择参数，通过数值框、开关与下拉框修改目标策略、范围、上限、锁定、分组和附加条件。
3. **成长 / 分组 / 召唤 / 联动**：修改线性和嵌套成长、伤害共享组、等级说明、召唤／分身策略及机制倍率。召唤单位与存续回合在动作和策略中需要一致；技能绑定 ID 由编译器管理。召唤战斗策略中历史说明记录只读，实际面板倍率在对应参数中修改。
4. **复合机制内部数值与条件**：44 类专属机制共有 324 个参数，显示中文用途、默认值、类型与范围，可调整伤害、治疗、护盾、距离、数量、持续回合及条件阈值；不需要修改客户端代码。

树节点支持添加列表项／字段、删除和修改类型；新增字段从真实原生配置取预设。扩展数组时仍需保持对应动作约定，例如连锁段数与倍率列表长度一致。完整机制清单与对应字段见 [战斗机制目录](battle-mechanism-editor-catalog.md)。共同的命中、伤害算法和复合机制执行流程由游戏引擎定义，编辑器不执行外部脚本。

调整结算顺序会同步目标锁、中心、主目标、排除目标、成长路径、伤害组和说明索引。非法前向依赖会拒绝；删除被引用的动作需要先解除引用。树中索引从 0 开始，左侧动作序号从 1 开始。

“AOE 约定”是原版旧参数，不是范围半径。模板导入保留原值；自行编排群攻时应同时检查动作的目标策略、目标数量和射程。旧版空白技能建议保持 AOE 为 0；“敌方本路全体”配合最大目标数 3 才表示最多三人，-1 表示筛选与射程内全部有效目标。

旧版命名字段的 16 动作技能仍可打开和编辑，入口是“创建旧版空白动作技能”。其位移、仅复用前序目标、等级说明与真实伤害能力继续保留，不会自动改写旧工程。

英雄普攻可以选择真实伤害，补丁可修改 `damageType`，复制英雄也保留该类型。原版类型 3 不扣物防／魔防，但沿用当前默认 0.3 的真实伤害倍率及其他原生规则。

**新模板需要客户端与服务端共同支持 `skill.native-template.v1`。** 编辑器自动声明能力；旧客户端激活、登录或使用相关存档时会得到升级提示。不要只替换编辑器就认为已安装游戏获得新接口。旧包和关闭全部新模板包的存档继续使用原有协议。

## 替换补丁

选择目标英雄后添加具体修改字段。编辑器读取原值并建立精确的原值／摘要守卫，展示修改前后的差异。

清空可选技能或语音时使用明确的“清空”，不要把空字符串当作有效引用。技能整槽替换可以选择内置技能或本包新技能；字段替换可以保留技能主体，只修改规范开放的参数。

导入已有补丁不会自动刷新其守卫。守卫失配意味着目标基础或依赖变化，应查看差异后明确修改；不能把“更新守卫”当作无条件修复所有兼容问题。

原值按补丁启用的作用域读取；若持有角色与 PVE／竞技场等场景已被依赖包改成不同值，需要拆分作用域补丁。对本包或依赖包注册的私有技能，整槽守卫保存稳定的技能引用，避免固化某台电脑临时分配的数字 ID。当前 API 一个补丁只能表达一个这样的私有整槽守卫；多个私有槽需拆成单独补丁，在“替换补丁 → 初始修改”选择“仅普通／队长／被动技能槽”分别创建。没有稳定注册引用的派生技能需使用具体字段修改。

## 图片、语音与预览

1.0.2 起，导入图片会先在**原图上放置与原版盾框同形的选择区域**，直接显示原版框的位置。拖动内部可移动选区，拖动四角可按原版比例缩放；滚轮可放大检查细节。

对准人物后，切换**正选笔**补入头发、武器或特效等区域，切换**反选笔**删除背景或其他不需要的部分。亮区是实际使用范围，暗区不会导入；允许在盾框以外增加区域，也允许挖掉框内部分。重置按钮恢复当前盾形初始选区。移动／缩放已修改的选区时，笔刷修改会跟随选区一起变换。

默认留出 12% 的出框空间，可调整“出框留白”。额外选中的像素会保留到最终画布，并在分区模式下显示在边框前；超过最终画布边界的部分仍会裁掉，应查看第二页的透明预览。实际使用范围先约束人物 alpha，后续遮挡模式不会让已经反选删除的部分重新出现。

选区采用转正后的原图坐标，EXIF 方向会统一处理；原始文件不被改写。源图、选区蒙版和框的位置随工程保存。旧版矩形裁剪配方继续按旧含义打开。选择目标槽位和输出大小后，生成符合游戏限制的 PNG。

1.0.1 的带框功能使用白、绿、蓝、紫、橙五种**原版盾形品质框的独立透明素材**。框按原版比例放入输出画布；改成竖版尺寸也不会把盾牌拉长，不再添加普通矩形彩边或 QUALITY 文字条。可将框、框内裁剪蒙版分别另存 PNG。

1.1.4 起，新素材只提供 **框在下、人物图在上**。初始盾形选区排除边框本体像素，避免人物默认遮住金边；需要出框的头发、耳朵或武器用原图正选笔补入，不要的区域用反选笔去掉。旧工程保存的 behind／split 配方继续按原方式读取，新素材不再提供这些模式。

最终 PNG 自动携带 `lal.cardFrame` 边框基准区域，客户端按原版 103×118 盾框进行布局、缩放、定位和点击判断。透明留白及出框部分仍会渲染，但不参与边框尺寸计算。调整输出分辨率或出框留白不会让卡牌主体变小或变形。使用这项能力需要同步更新游戏客户端和服务端，编辑器自动声明 `asset.image.card-frame`。

程序保留透明通道，不自动识别人形或去除照片背景。先准备透明人物图，再通过选区补入或减去实际使用范围。

源图、图层参数和蒙版随 `.lalhero` 保存，重新编辑无需依赖原文件仍在原路径。每份工作素材最多 32 MiB，工程仍受整体配额约束；源图和蒙版属于工程工作素材，不进入 `.heropack`。游戏包只包含最终合成的 PNG。旧工程仍可读取；旧工程缺少源文件时，已合成的图片会作为成品打开，不自动重复套框。

透明图片保留透明度；动画图片需要先导出单帧。最终输出仍限制为游戏允许的尺寸和像素总量。

项目内置真实原游戏图标，作为英雄和内置图片选择时的静态预览。特效目录展示真实定义和可用资源说明；静态预览不冒充完整战斗动画。缺少可显示资源时会明确提示，避免显示另一个英雄的图案。

语音可复用规范允许的内置声音，也可将合法 MP3 加入包内素材并关联；WAV 需先转换成 MP3。游戏中的内部素材名并非全部都是公开可用引用，导出校验会核对实际能力。

## 离线依赖

需要其他包时，先在包依赖表填写 UUID、版本条件和可选摘要，再将对应 `.heropack` 加入编辑器的“离线依赖包”库。验证只使用明确提供的文件，不扫描游戏已安装 Mod。

外部依赖不会自动变成新包的一部分；在游戏中使用导出包时仍需安装相应依赖。希望吸收依赖内容时，把依赖和使用它的包一起选择合并。

## 合并多个包

选择“合并包”，添加多个 `.heropack` 并填写新名称和作者。合并结果生成新的 UUID，英雄、变体、技能和素材自动加来源命名空间，内部引用随之改写，来源作者和内容摘要保留在记录中。

合并会保留各源包英雄／补丁的渠道默认值，吸收一起选入的内部依赖，保留剩余外部依赖。重复选择完全相同的包会去重。

同 UUID 不同版本／内容、同目标同作用域重叠写入、外部依赖不满足、或无法保持原守卫语义的组合会明确拒绝。编辑器不采用“后一个覆盖前一个”，也不放宽守卫来掩盖冲突。

**合并后的英雄是新身份，不继承原包在存档中的角色。** 请保留原包以继续使用旧存档中的英雄。合并完成后可以继续编辑、保存为工程，再校验导出。

## 校验与导出

“校验”检查必填字段、数值、引用、技能动作、媒体、依赖、目标守卫、冲突和配额，并定位错误。实际调用与游戏相同的格式检查和配置编译；临时目录在完成后释放，不更改任何玩家目录。

所有错误解决后点击“导出英雄包”。编辑器重建清单、文件哈希和所需能力，并完整校验临时产物，成功后才原子替换目标文件；失败时已有输出保持原样。

## 源码运行与构建

Windows x64、Python 3.12：

```powershell
py -3.12 -m venv .venv-editor
.\.venv-editor\Scripts\python.exe -m pip install -r editor\requirements.txt
.\.venv-editor\Scripts\python.exe -B scripts\hero_editor.py
```

只构建编辑器，不编译游戏或启动服务器：

```powershell
.\.venv-editor\Scripts\python.exe -B scripts\build_hero_editor.py
```

支持离线命令行校验和合并，适合创作者批处理：

```powershell
.\.venv-editor\Scripts\python.exe -B scripts\hero_editor.py --validate .\my-hero.heropack --report .\validation.json
.\.venv-editor\Scripts\python.exe -B scripts\hero_editor.py --merge .\one.heropack .\two.heropack --name "合并英雄" --author "作者" --output .\merged.heropack --report .\merge.json
```

程序日志写入 `%LOCALAPPDATA%\LALHeroEditor\editor.log`，采用有限轮转。日志不包含玩家存档；工程文件、导出包和原始素材由创作者自行保存。依赖许可证随发行目录的 `licenses` 提供，原游戏美术和音频的权利仍归原权利人。


### 独立详情页立绘（1.1.4）

英雄的 `presentation.portrait` 是详情页无框立绘；`presentation.icon` 是列表／战斗卡面。英雄资源区有独立“导入详情页立绘”按钮，自动绑定当前英雄的 portrait，保留 icon；素材库也可独立导入后指派。立绘编辑保留透明通道，按原版品质画布完整等比缩放：白 200×200、绿 300×225、蓝 400×250、紫 500×275、橙 600×300；人物水平居中、底部对齐，空余透明，禁止叠盾框，并保留可重编原图和裁剪配方。旧工程中同一张图的双槽引用不会被自动替换，需作者分别选择。


立绘尺寸依据原版 hero_A/B/C SWF 角色显示边界的常用标准，而非内嵌位图原分辨率；个别原版角色具有特殊出框边界。立绘导入界面锁定宽高，品质改变时同步标准画布。素材库把任意尺寸图片指派为立绘时，会另生成规范化副本，不覆盖共享卡面；带 lal.cardFrame 元数据的成品卡面不能直接指派为立绘。


独立仓库首次发布 1.1.4；游戏协议来源见 [快照说明](game-data-snapshot.md)。原生模板与校验模块已同步游戏 PR #17 合并后的修复。
